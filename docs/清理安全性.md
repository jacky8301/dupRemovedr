# 清理与恢复

清理前，程序锁定保留文件和副本，直接从同一文件句柄重新核对文件大小和完整 MD5。校验期间禁止写入、重命名及删除；无法获得所需权限或锁定时跳过该副本。

校验通过后，通过句柄将副本移动到原目录下新建的 `.dupRemover-staging-{GUID}` 子目录，保留原文件名，再交给 Windows Shell 回收。原路径上随后出现的新文件不参与该回收操作。暂存目录及其父目录在操作期间保持打开，禁止重命名；不会通过符号链接或其他文件重解析点执行清理。

回收禁用 HTML 与关联资源目录的联动，不会因清理 `example.html` 而连带清理 `example_files`。

## 失败、取消与恢复

- 回收前取消、回收失败或抛出异常时，程序尝试将同一文件对象移回原位。
- 恢复时绝不覆盖已有文件。若原位置已经出现新文件，副本留在暂存目录，界面显示“已暂存”及实际路径，可从结果列表定位。
- 程序只移除空暂存目录，不递归删除其内容。扫描原目录时跳过暂存子目录，避免再次清理中断后留下的副本。
- 若进程在移动后异常退出，请检查原目录下的 `.dupRemover-staging-*` 子目录并手动恢复文件。
- **从 Windows 回收站还原后，文件会回到暂存子目录，而非直接回到原目录。请再将文件移回其上一级目录。**

暂存路径超出旧 Shell API 的长度限制、文件被其他程序占用或目录不可写时，该文件不会被移动或清理。独立随机暂存目录用于隔离其他程序对原路径的正常替换操作；它不是对同一用户权限下恶意进程的隔离边界。
